## 1. The headline warning

**The evaluation corpus is synthetic, tier-B-shaped, and deliberately
table/list/OCR-heavy. No threshold in this system has been validated against
real-world document composition.**

`eval/corpus/` contains 13 documents, all generated by
`eval/corpus/generate_tier_b.py`. There is no tier A. That composition is not
an accident — tier B exists to be adversarial, and it is *why* the largest
defect found so far (finding #27) surfaced at all. But it means:

- `recall_at_fetch = 1.000` is **arithmetic**, not quality. 18 chunks against
  `retrieval_fetch_k = 20` returns the entire corpus for every query. It will
  fall on real documents.
- Roughly 60% of the corpus is tables, spreadsheets, slides or scanned pages.
  Real corpora are mostly prose.
- Any threshold fitted to these numbers would be fitted to that composition.
  None has been.

The two thresholds that exist were chosen on principle and are documented as
such:

| setting | value | basis |
|---|---|---|
| `abstention_score_floor` | 0.01 | a cross-encoder sigmoid below 0.01 is a logit near −4.6 — the model confidently rejects even its own best candidate. Tied to the model's confidence semantics, not to a corpus. |
| `rewrite_min_similarity` | 0.55 | chosen a priori; the measured distribution is *consistent with* it, not derived from it. Catches gross topic replacement only. |

`rerank_score_floor` is **0.0 (off)**. It was 0.25 and that was the defect.

## 2. What is measured, what is assumed

### Measured, with evidence in the log

- Retrieval mode is deterministic: 0.0 spread across six passes on two
  separate container builds.
- The LLM is **not** deterministic: 3–5 distinct outputs in 10 calls at
  `temperature=0.1`, no seed. **No seed is set on purpose** — a seed would make
  the eval reproducible while hiding the nondeterminism real users get.
- Ollama silently truncates embeddings at 2048 tokens (finding #19).
- The embedding leg and the cross-encoder receive *identical* text. A
  hypothesised divergence between them was disproved by measurement.

### Assumed, and marked as such

- Everything about behaviour on real-world documents.
- The full-mode tolerance. See §3.

## 3. The instrument cannot yet detect change in full mode

Full mode measured **0.0 spread across three passes** over a pipeline proven to
be non-deterministic. That is a statement about the instrument, not the system:
**the harness cannot currently detect change.**

The tell is `mrr_at_k == hit_at_k` *exactly*, in both modes. Two metrics
reporting one bit of information, because before candidate C3 results never
exceeded one item.

Therefore:

- The nightly full-mode job is **non-gating**. It records spread; it does not
  act on it.
- **Zero spread must never be cited as evidence that a change was safe.** It is
  consistent with any change at all to the LLM path.
- C3 was implemented specifically to restore sensitivity. Re-measurement after
  C3 is the first number that can mean anything.

## 6. Rules that hold across sessions

- **Baselines.** `api_image_digest` is the authoritative identity of the code
  that ran. `git_sha` is the repo pointer at launch and can run ahead of the
  image, or be wrong entirely if files were copied into a live container.
  Rebuild before recording. `run_eval.py` prints a loud
  `WARNING: DIAGNOSTIC ONLY` naming any unresolved provenance field.
- **The eval corpus never shares a collection with real documents.**
  `ingest_corpus.py` refuses the default collection outright.
- **Full mode requires `ENABLE_ANSWER_CACHE=false`.** The harness refuses to
  start otherwise: runs 2..N would be served from Redis and the measured
  variance would be a property of the cache.
- **Tiers are never averaged.** Tier B is adversarial; folding it into a
  headline next to real documents produces a figure that means nothing.
- **`false_abstention_rate` and `correct_abstention_rate` are gated
  separately.** A single abstention number improves as the system stops
  answering — it read 1.000 on a run that abstained on 15 of 22 answerable
  questions.

## 7. Things that looked like they worked and did not

Recorded because each cost real time and each was caught only by testing the
check itself rather than the thing it checks.

1. `HF_HUB_OFFLINE=1` as a model-revision pin — fastembed does not resolve
   through the plain HF cache layout and fails outright.
2. `ENV FOO=${FOO}` against a same-named `ARG` — resolves to the **empty
   string**, silently recording `unpinned` provenance while the download was
   correctly pinned.
3. Setting `EXPECTED_EMBED_MODEL_DIGEST` in the **shell** for a compose test —
   compose reads container env from the per-service `environment:` map, so the
   variable never reached the container and the "passing" test proved nothing.
4. A model-pin verifier that checked the pinned snapshot **exists** — which
   `snapshot_download` guarantees on its own. It now requires the pinned
   snapshot to be the *sole* cached snapshot.
5. Asserting a metric that the newer baseline no longer reports — the
   comparator skipped it in silence, so a rename would have passed as "no
   regression" forever. It now warns.
